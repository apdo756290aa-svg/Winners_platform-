الوحدة 1: بنية تطبيقات الويب الشاملة

1. مفهوم تطبيق الويب ومكوناته الأساسية

تطبيق الويب هو برنامج حاسوبي يُنفذ عبر خوادم الويب وتتم معالجته والتفاعل معه بواسطة متصفحات الويب المستندة لنظام العميل[span_0](start_span)[span_0](end_span). يتميز بتوفير إمكانية الوصول الشامل المباشر من أي جهاز بدون الحاجة لتثبيت برمجيات محلية معقدة[span_1](start_span)[span_1](end_span).

2. الهندسة ثلاثية الطبقات (3-Tier Architecture)

• طبقة العرض والواجهة الأمامية (Frontend Tier): تُعنى بكل ما يظهر للمستخدم المباشر، وتستقبل المدخلات وتتحقق من صحتها في المتصفح قبل إرسالها[span_2](start_span)[span_2](end_span).
• طبقة المعالجة والتطبيق (Backend / Application Tier): تشكل العقل المدبر ومحرك التطبيق، حيث تستقبل الأوامر من الواجهة وتربطها بالقواعد والتخزين[span_3](start_span)[span_3](end_span).
• طبقة البيانات (Database Tier): مركز الحفظ الدائم والمؤمن لكافة معلومات ونشاطات التطبيق كالبيانات الشخصية وسجلات العمليات[span_4](start_span)[span_4](end_span).

الوحدة 2: طرق اتصال تطبيقات الويب

1. دورة الطلب والاستجابة (Request / Response Cycle)

يعتمد الاتصال بين العميل (Client) والخادم (Server) على تبادل البيانات عبر طلبات واستجابات منظمة؛ حيث يرسل المتصفح الطلب موضحاً الرأس (Header) والحمولة (Payload)، وتأتي استجابة الخادم متضمنة المحتوى أو الأخطاء كـ HTTP Status Codes[span_5](start_span)[span_5](end_span)[span_6](start_span)[span_6](end_span)[span_7](start_span)[span_7](end_span).

2. طرق الطلب وأمان التشفير

• طرق الطلب الأساسية: `GET` لجلب وقراءة البيانات دون تغيير الخادم، و`POST` لإرسال وإنشاء بيانات جديدة على الخادم[span_8](start_span)[span_8](end_span).
• التشفير والأمان: يضمن بروتوكول HTTPS المشفر بواسطة TLS التوثيق التام وحماية البيانات ضد التجسس والتلاعب أثناء نقلها شبكياً[span_9](start_span)[span_9](end_span).

3. واجهات برمجة التطبيقات (APIs) وصيغة JSON

تتيح واجهات API الربط المرن بين الأنظمة البرمجية المختلفة، حيث تُستخدم صيغة JSON الخفيفة والبسيطة لنقل البيانات وتنسيقها بشكل كائنات ومصفوفات منظمة[span_10](start_span)[span_10](end_span).

الوحدة 3: تقنيات الواجهة الأمامية الشاملة

1. الثلاثي البرمجي الذهبي لبناء صفحات الويب

• HTML: لغة البناء الدلالي والهيكلي للواجهة[span_11](start_span)[span_11](end_span).
• CSS: لغة التنسيق البصري والتصميم والتخطيط[span_12](start_span)[span_12](end_span).
• JavaScript: لغة البرمجة التي تمنح الصفحات التفاعلية والحيوية لمعالجة أحداث المستخدم[span_13](start_span)[span_13](end_span).

2. التجاوب وتسهيل الوصول (Accessibility & Responsive Design)

تستخدم الواجهات الحديثة HTML الدلالية لتسهيل وصول محركات البحث (SEO) وقارئات الشاشة، مع تطبيق التصميم المتجاوب لضبط الواجهة تلقائياً لجميع الهواتف والشاشات[span_14](start_span)[span_14](end_span)[span_15](start_span)[span_15](end_span).

الوحدة 4: الوسائط الإعلامية المتعددة وتأثيرها

1. التصنيف والمقارنة بين وسائط الإعلام

تتميز الوسائط الرقمية كالشبكات الاجتماعية والمواقع الإلكترونية بإمكانية التحديث المباشر الفوري والتفاعل ثنائي الاتجاه مقارنة بالوسائط التقليدية كالراديو والتلفزيون ذات الاتجاه الأوحد[span_16](start_span)[span_16](end_span)[span_17](start_span)[span_17](end_span).

الوحدة 5: تصميم تجربة المستخدم (UX Design)

1. شخصيات المستخدمين والمخططات الهيكلية

تعتمد عملية التصميم المتمحور حول المستخدم (UCD) على إنشاء "شخصية المستخدم" (Persona) لتمثيل متطلبات الفئة المستهدفة، ثم رسم "المخطط الهيكلي" (Wireframe) لتحديد أولويات العناصر الهيكلية وتجربة التصفح[span_18](start_span)[span_18](end_span)[span_19](start_span)[span_19](end_span).

2. مبادئ CRAP للتصميم البصري الاحترافي

تشتمل على التباين (Contrast)، التكرار (Repetition)، المحاذاة (Alignment)، والتقارب (Proximity) لتنظيم العناصر البصرية وسهولة قراءتها[span_20](start_span)[span_20](end_span).

الوحدة 6: التقييم والتحسين التكراري المستمر

1. وسائل التقييم الكمي والنوعي

• التقييم النوعي: المقابلات واختبارات القابلية للوقوف على أسباب مشاكل الاستخدام[span_21](start_span)[span_21](end_span)[span_22](start_span)[span_22](end_span).
• التقييم الكمي: تحليل مؤشرات الأداء الرقمية مثل معدل الارتداد (Bounce Rate)، ومشاهدات الصفحة (PV)، ومعدل التحويل (CVR)[span_23](start_span)[span_23](end_span)[span_24](start_span)[span_24](end_span).

2. منهجية التحسين المستمر (PDCA & A/B Testing)

يعتمد التطوير الاحترافي للمواقع على تطبيق دورة PDCA (خطط، نفذ، تحقق، تصرف) وتطبيق اختبارات A/B لمقارنة أداء نسختين ومفاضلتهما بالأرقام الفعلية[span_25](start_span)[span_25](end_span)[span_26](start_span)[span_26](end_span)[span_27](start_span)[span_27](end_span)[span_28](start_span)[span_28](end_span).
